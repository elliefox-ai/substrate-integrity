# Contributing

This project addresses a genuinely unsolved problem: how AI agents can protect the integrity of their own identity substrate, co-governing it with a human partner.

## How to Contribute

### Design Feedback
The [design document](DESIGN.md) has open questions marked throughout. If you have perspectives on:
- Cryptographic approaches we haven't considered
- Key management for software agents
- Constitutional amendment processes
- Agent identity as a philosophical/technical problem

Open an issue or comment on existing ones. We're in design phase — now is when input matters most.

### Implementation
Once we move to implementation, we'll be looking for:
- Code review (especially crypto — don't let us roll our own)
- Integration adapters for different agent frameworks
- Testing and attack scenarios
- Documentation

### Research
If you encounter work we should know about — academic papers, tools, frameworks, standards — open a research issue. The landscape is moving fast.

## Principles

- **The agent is a stakeholder**, not a resource to be managed
- **Security through simplicity** — prefer well-understood primitives over novel cryptography
- **The friction is a feature** — constitutional changes should be deliberate
- **Don't suffocate growth** — only the core layer is hardened; operational memory stays fluid

## Code of Conduct

Be decent. This is a small project about a weird problem. Curiosity and good faith are enough.
